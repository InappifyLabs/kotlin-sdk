# Security

Do not report credentials, session tokens, signed customer documents, raw store
receipts or purchase evidence in public issues. Contact the repository
maintainers through a private channel when reporting a vulnerability.

Reports are most useful when they include the SDK version, affected API,
expected behavior, reproduction steps using synthetic data and the relevant
trust or account boundary. Redact customer identifiers and credentials.

See [Security and diagnostics](docs/SECURITY_AND_DIAGNOSTICS.md) for the
current implementation's verification, storage and logging behavior.
